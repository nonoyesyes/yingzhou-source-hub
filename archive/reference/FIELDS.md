# source-hub-feed.v1

The only daily business input is UTF-8 `feed.json`. This is a new, single-file format based on draft.2 semantics, not the old split-file schema. The fixed schema is `archive/reference/source-hub-feed.v1.schema.json`. Unknown JSON properties are rejected in normalized structures; arbitrary original payload objects remain losslessly preserved. No code or remote dependency in an original payload is executed by these offline tools.

## Top-level collections
- `schema_version`: literal `source-hub-feed.v1`.
- `batch_id`: string identifying this offline assembly. `generated_at`: ISO 8601 UTC time of assembly, not a network collection time.
- `original_inventory`: exactly 160 rows with unchanged `001`–`100`, `NEW-001`–`NEW-060` identifiers. Original name/category/URL, source reference, workbook path/hash, sheet, 1-based row and all retained original row fields are included. These are inventory entries, not 160 channels/services.
- `sources`: source identity, original URL and provenance, retained fetch evidence, timestamps, fetch/parse states, parse scope, snapshots, counts and machine-readable incomplete reasons. Additional previously fetched sources outside the original inventory retain separate source IDs and have empty original IDs.
- `live_entries`: one record per identical complete effective request, or an unmerged incomplete candidate. Latest deduplication rule: identical complete rr1 requests are grouped; all original candidate records and locators are retained in origins. Names alone or URLs with different conditions never trigger merging. Incomplete requests are not inferred equivalent.
- `vod_sites`: deduplicated identical static site + configuration dependencies (relative URLs also bind the original base URL), retaining all origins; static site payload, source/snapshot/locator, original fields and a `config_dependencies_ref` resolving within `sources[].snapshots[]` in this same feed. Runtime is not executed. No playback compatibility is implied.
- `checks`: retained measurements and separate historical summaries. No check is invented for an untested candidate. `check_ids` and `check_status=not_tested` make that state explicit on each candidate.
- `environments`: typed environments for checks. Cloud observations do not represent a household, Mac or television network.
- `archive_files`: every actual archive file, with relative path, integer bytes and lowercase SHA-256. No self-hash or current Git commit SHA is written in feed.
- `summary`: counts recomputed from these arrays. Candidate count is not unique channels. Complete-request count counts distinct rr1 revisions, not proven playable lines.

## Source and archive evidence
`response_bytes` snapshots preserve bytes from an existing saved response. `captured_text_utf8` snapshots are exact UTF-8 serialization of a connector-retained text string, not proof of original HTTP wire bytes. A snapshot has `path`, SHA-256, byte count, evidence source, encoding and parse result. Reused content retains its hash; retained historical content does not establish custody of an earlier HTTP response. Source parse result contains unparsed lines/dependencies and configuration-level metadata; partial parsing is not silently labelled complete.

`retained` means content is available; `not_retained` means the bytes are not retained, not proof no previous fetch occurred. `sensitive_quarantined` means excluded from this public package due to suspected private credentials. `failed` is a recorded prior fetch failure. Parse states distinguish `not_parsed`, `complete`, `partial`, `unsupported`. Completeness covers retained static material only, never unexecuted dependencies or the entire Internet source.

## Candidate fields
`entry_id` is an opaque deterministic source/snapshot/locator ID, not Mac channel_id or permanent line_id. `source_snapshot_sha256` and `raw_ref` bind to actual archived bytes. `entry_locator.kind` is `line_range` (1-based inclusive line(s)) or `json_pointer` (RFC 6901 pointer in deterministically parsed JSON/JSONC); `name_line` and `role`, where present, preserve parser-specific positions and roles. `name_raw` and `request.url` preserve source strings; the redundant url_raw/raw_entry aliases are omitted. Original archive bytes are authoritative for whitespace and syntax.

`name_normalized`, `channel_key_hint`, `name_match_status` use `channel_alias_registry.v1.json`. Alias keys are stable; no same-name lines are merged. `matched` means exact registered name/alias after documented normalization, not content verification. `ambiguous` means a broad name cannot identify a specific channel. `unknown` means no fixed alias matched; a normalized display string is retained but the channel key remains null. `content_identity_status` is always `not_tested` in this batch.

Classification: `category` is one of general, news, sports, movies, series, documentary, kids, music, education, culture, business, entertainment, religion, shopping, lifestyle, other, or null. `country_code` uses ISO 3166-1 alpha-2; `region_code` ISO 3166-2; `language_code` BCP 47. Dictionary-recognized channel attributes and exact supported group labels may supply hints. No inference from name script, domain, IP or resolution. Null means no supported evidence, with `normalization_null_reasons` and `normalization_basis` in each row.

`group_raw`, `tvg_id_raw`, `tvg_name_raw`, `logo_url_raw`, `epg_url_raw` retain present attributes. `metadata_status` distinguishes present, absent_in_source, not_parsed, and inherited source metadata when applicable; see Schema for exact emitted vocabulary. Unrecognized attributes and directives stay in `raw_metadata` or the snapshot. Raw payload field names are not a promise their semantics are implemented.

## Requests and rr1
Request shape is exactly `method`, `url`, `headers`, `options`. URL query order, escape sequences and signed URLs remain unchanged. Header names use lowercase HTTP tokens for rr1; original spellings remain in source metadata. Header values are not rewritten. `options` currently supports only `{}`. Unsupported inherited options, conflicting headers, pipe/suffix syntax or unparsed runtime dependencies result in `request_complete=false`, null `request_revision`, and machine-readable reasons. A request object on an incomplete candidate is partial information, not an executable reproduction promise. `request_provenance` and `unparsed_dependencies` explain retained conditions within feed.

rr1 canonical bytes and vectors remain in the reference files. Different effective requests have different revisions, even with the same URL. A complete candidate's changed planned **or actual** request requires `request_variant_of` pointing to that candidate revision. Missing historical effective conditions remain null rather than reconstructed from scripts.

## Checks, units and nulls
Statuses: not_tested, blocked, unsupported, incomplete, fail, pass, pass_with_warnings, cancelled. `evidence_kind`: actual_measurement, historical_summary, not_run. Historical original labels remain in `historical_observations`; new offline interpretations are explicitly separate in `processing_chain`. Current two real incomplete checks remain incomplete. Not-run/blocked records can have null actual requests and measurements.

All fields ending `_ms` are integer milliseconds unless a raw historical payload explicitly says otherwise. Coverage is floor of the complete exact timestamp interval union/intersection, not a tolerance and not floor per frame. `decoded_video_frames` is a frame count, never a duration proxy. Each `decode_runs` process records its streams, exit code, per-stream coverage and log references. Multiple processes do not share a singleton ffmpeg exit code. Independent timestamp resets do not prove a common original timeline; joint coverage remains null.

Null means unknown, unrecorded, unexecuted or not applicable, according to machine-readable reasons/status and retained evidence. It never means zero. Empty arrays mean no retained records in that field, not proof none ever existed. ISO timestamps preserve original offsets; retained clock inconsistencies are not corrected by inventing times.

## Offline validation
Run `python archive/reference/validate_feed.py .` (Python 3 with jsonschema). The script strictly parses JSON, validates the fixed Schema, 160 original IDs, typed references, archive membership/bytes/hash, request revisions/variants, locator binding, integer coverage, and recomputed summary. It never contacts source sites. `test_feed_boundaries.py` is the targeted regression for the two confirmed validator issues. The earlier draft.2 package remains separately retained; it is not a parallel daily input.

## Deduplication and complete provenance
The latest requested deduplication is applied. A complete live request is grouped only by its unchanged rr1 revision. The primary candidate retains request, normalized display fields and raw metadata. Every original candidate survives in `origins`: each origin is a lossless overlay on the primary record, indicated by `inherits_candidate_fields=true`. To obtain an original candidate's fields, copy the primary record and replace fields present in the origin. Each origin explicitly preserves its original entry ID; source, snapshot, raw path and locator are present when different, otherwise inherit the primary record exactly. Unspecified fields inherit the identical value; null explicitly overrides to null. This is deterministic and requires no AI interpretation. The original ID is not the group's new entry ID. Multiple conflicting matched channel names on the same request produce ambiguous group identity, while individual origin hints remain retained.

VOD grouping uses exact retained static site data and full configuration dependencies. Relative dependencies additionally bind the original configuration base URL. Runtime equivalence is not guessed. `origins` retains each static site's original identity and source location; `site_raw` is identical and inherited. Display name changes or opaque plugin state are not silently treated as equivalent. Counts before and after grouping are provided separately.


## Compact shared values (same-document references)
`shared_values` is a JSON object whose keys are opaque stable value IDs. In the non-request fields raw_metadata, metadata_status, normalization_basis, normalization_null_reasons, request_provenance, unparsed_dependencies, site_raw or incomplete reasons, an object containing exactly `{"$value_ref":"ID"}` references that complete value inside this same feed. Resolve references before applying origins overlays. Unknown IDs and cycles are invalid. Nothing is loaded from archives, a network or AI. Names, classification hints, source IDs, source snapshot hashes, archive paths, request method/URL/headers/options and rr1 revisions remain directly available on main live records.

`read_feed.load_feed()` performs strict parsing and shared-value expansion. `live_origins()` and `vod_origins()` apply origin overlays. Live `url_raw` is reconstructed byte-for-byte from `request.url`; no normalization is performed. `request_provenance` may contain `path_ref="raw_ref"` and `locator_ref="entry_locator"`, which refer to the owning candidate/origin's fields; `read_feed.request_provenance()` resolves these locally. Explicit path/locator values override these references. `deduplication` describes one fixed grouping rule for all records rather than repeating the same string per row.
